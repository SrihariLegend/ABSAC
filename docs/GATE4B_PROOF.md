# Gate 4B — Mechanically checked concrete end-to-end equivalence

**Status: PASSED (2026-09-15).** The six lemmas that were previously
human-written prose plus differential testing (`docs/GATE4_RESULTS.md`)
are now machine-checked derivations over the committed artifacts, and
the proofs replay.

## What is checked

For each of the three development kernels, from the *committed* files
`gate4/{k18_all_equal,k43_sum_ascii,k50_count_masked}.c`:

```text
  chunk lemmas      contribution(w, i) = fold(i + w, i)   for w = 32, 16, 1
  loop invariants   [i <= n] ⊢ W/V_level(i, …, n) = fold(n, i)  for level = 1, 16, 32
  tail composition  the case splits on each loop guard route the remainder
                    into the narrower stage and the scalar tail
  end-to-end        [0 <= n] ⊢ W32(0, 0, n) = S(n, 0)
                    [0 <= n] ⊢ V32(0, n) = A(n, 0)
  memory safety     [i + w <= n] ⊢ every loaded index i..i+w-1 is < n
  no wraparound     [0 <= n, B*n <= 2^64-1] ⊢ S(n, 0) <= 2^64-1
                    (B = 1 for indicators, 255 for bytes)
```

Every step is re-checked by replay: the artifact records the
derivation, and `Kernel::replay` re-runs each rule (bit-blasting,
arithmetic, congruence, induction, discharge).

## How to run

```bash
cd sir
cargo run -p sir_gate4b --bin gate4b_check   # writes gate4/proof/*.proof.txt
cargo test  -p sir_gate4b                    # proofs + reproducibility check
```

`artifacts_are_reproducible` regenerates each artifact and requires it
to equal the committed copy byte for byte.

## Architecture

```text
corpus/kernels.ll ──lower──► SIR function ──semantics──► truths
        │                                     │
        │                             plan derivation (vector_derive)
        │                                     ▼
        │                             emitter (vector_emit) ──► C text
        ▼                                     │
  binding.rs  ── emitted text == gate4/<kernel>.c  (byte identical)
        │      plan roles == C template roles == SIR parameter names
        ▼
  emitted.rs  ── strict, fail-closed template match; per-line spans + digest
        ▼
  model.rs    ── byte-addressed memory, guarded fold theory, SDM intrinsics
        ▼
  loops.rs / pred.rs ── three-stage loop semantics; induction lemmas
        ▼
  bounds.rs   ── memory bounds, element bounds, accumulator bound, no-wrap
        ▼
  sir_mech::kernel ── LCF-style rules + replay; bitvector SAT; linear arith
        ▼
  gate4/proof/*.proof.txt ── the artifact
```

## Requirement mapping (docs/GATE4_RESULTS.md, docs/IMMEDIATE_PROGRAM.md)

| # | Requirement | Evidence |
|---|---|---|
| 1 | source SIR region mechanically bound to theorem operands | `binding.rs`: emitted text is byte-identical to the committed C, and the plan's buffer/length/predicate are the same identifiers the C template captured and the emitter's names for SIR params 0..n |
| 2 | actual generated plan encoded, not a stand-in | `emitted.rs` recognizes the committed files fail-closed, recording every matched line with its span and the file digest |
| 3 | per-chunk identities proven by solver/checker | replayed bit-blast proofs, including `popcount(x) = Σ bits(x)` (proved, not assumed) |
| 4 | loop invariant covers arbitrary valid `n` | `loop_w1/w16/w32` and `loop_v1/v16/v32` by case-split induction; the statement is universally quantified over `n` |
| 5 | tail decomposition proven for all remainders | each stage's induction case-splits on its guard and hands the remainder to the next stage down to the scalar tail |
| 6 | target intrinsic semantics modeled | explicit SDM models for `pcmpeqb`, `pmovmskb`, `popcnt`, `psadbw` against zero, `paddq`, and `movdqu` loads |
| 7 | memory and overflow semantics match the source | per-stage index-bound lemmas plus the accumulator bound and the no-wrap lemma under `B*n <= 2^64-1` |
| 8 | reproducible proof artifact | `gate4/proof/*.proof.txt` (digests, roles, SIR binding, spans, lemma statements, replay status) regenerated byte-for-byte in `artifacts_are_reproducible` |

## Trusted base (explicit)

Everything else is re-checked, but the following are modelling choices
that a reviewer should read as the axioms of the result:

1. **Instruction models** (`model.rs`): `pcmpeqb` produces `0xFF`/
   `0x00` per lane, `pmovmskb` extracts lane MSBs, `popcnt` counts set
   bits, `psadbw` against zero sums 8 bytes per 64-bit lane, `paddq`
   adds lanes modulo 2^64, `movdqu` loads 32 (16) consecutive bytes.
   The *composition* identities over these models are proved, not
   assumed.
2. **Memory model**: `load(addr) : Bv8` is a free function; the
   memory-safety lemmas show every address the code reads is `< n`, so
   only the caller's "buffer has n bytes" contract is needed.
3. **Scalar element semantics**: the element function (`(b & mask) ==
   target`, `b == val`, `b`) is taken from the recognized scalar tail
   of the same artifact; correspondence of that tail with the original
   C source is the C→LLVM→SIR front end's obligation, not this proof's.
4. **Arithmetic primitives**: the bit-blasting Tseitin encoding and the
   CDCL solver (`sir_mech::cnf`, `sir_mech::sat`), and Fourier-Motzkin
   linear integer arithmetic with GCD tightening (`sir_mech::arith`).
   Both are deterministic; a SAT answer is only reported after the
   returned model is re-evaluated against the original terms, and the
   arithmetic engine fails closed (`Unknown`) when it cannot prove.
5. **Pipeline binding**: the proof covers `corpus/kernels.ll` as lowered
   by `sir_lower` and recognized by the current `sir_semantics` +
   `vector_derive`. If the recognizer or emitter changes, the binding
   check fails and the proof must be regenerated.

## Scope honesty — what this result covers, and what it does not

**Covered.** For the three committed development kernels
(`k18_all_equal`, `k43_sum_ascii`, `k50_count_masked`) and x86-64
AVX2/SSE2: the vector stage bodies, the three-stage loop semantics, the
tail decomposition, the memory/overflow obligations, and the SIR
binding are derived from the committed artifacts and re-checked by
replay. The u64 model is used under the explicit precondition
`B*n <= 2^64-1`, so the `no_overflow` lemma is what licenses the
mathematical accumulator equality `W32(0,0,n) = S(n,0)` for the C code.

**Not covered — do not read the gate as stronger than this:**

1. **Not a verified compiler.** The binding is *per artifact*: the
   checker re-runs the real lowering → semantics → plan → emitter path
   for the named function and requires the committed C to match. If
   `sir_semantics`, `vector_derive` or the emitter changes, the check
   fails loudly and the proof must be regenerated. Nothing here
   proves the recognizer, planner or emitter correct for arbitrary
   input; `sir_gate4b` is a checker over three known shapes, not a
   pass in the pipeline.
2. **Not the per-rewrite application pipeline.** H3/D4 give a
   *different* mechanism — `CheckedApplication` /
   `EndToEndVerificationArtifact` over the rewrite engine — labelled
   "Gate 4B.1" in docs/H3_RESULTS.md. That pipeline's soundness failed
   under adversarial evaluation (S1/S2/R1), was remediated through D4,
   and was closed by the independent blind H4 corpus on 2026-09-16
   (docs/H4_RESULTS.md; F10 lowerer fix `1da3b28`). The two mechanisms
   remain distinct and must not be conflated: 4B.1 carries SIR-level
   `SchemaChecked` assurance, not the machine-checked evidence above.
3. **SIR-level semantics, not native execution.** No claim is made
   about LLVM IR or machine code. Execution evidence for the rewrite
   path is the SIR interpreter; the C emitter for loop sources had
   known defects F6–F8 (post-loop emission order, buffer element-width
   typing, loop-control polarity/entry-guard) recorded in
   docs/H3_RESULTS.md (closed 2026-09-17 —
   docs/EMITTER_F6F8_RESULTS.md). The Gate 4B kernels do have their emitted C
   mechanically matched to the committed files, but compiled-object
   equivalence is not established here.
4. **Trusted instruction, memory and front-end models.** The SDM
   instruction models, the free `load : addr -> Bv8` memory model, the
   C→LLVM→SIR correspondence for the scalar tail, and the
   bit-blasting/arithmetic primitives are the enumerated axioms of the
   result (see Trusted base above). Mechanizing the ISA models against
   a vendor or academic semantics (Sail/Lean/Coq-class) would be the
   next assurance tier; nothing in this result depends on such a
   mechanization having been done.
5. **Not a definition-level upgrade.** The 16 quarantined verifier
   definitions remain `Stub`/`SchemaChecked`; upgrading them to
   `ConcreteSolverChecked` is P0A queue item 3 and is untouched by
   this proof, even though `sir_mech` is the natural engine for it.
6. **No performance claim.** Gate 2/5A/5B-Witness carry the measured
   numbers; this document only establishes semantic equivalence.

**Provenance note (findings from this work).** `k43_sum_ascii`
required restoring the `SumReduction` branch in
`vector_derive::derive_vector_plan`: the concept had been added to the
semantics engine without being wired into plan derivation, so the
committed artifact no longer reproduced. The gap is fixed and is now
covered by the binding check. A second defect — a wrong fold
recurrence direction that was internally consistent but wrong about
the source — was found by the proof effort before any artifact was
trusted.
